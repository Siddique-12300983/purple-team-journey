## What I learned

- Active Directory runs on DNS. Clients find the domain controller through an SRV record (`_ldap._tcp.dc._msdcs`), so if DNS is wrong, joins and logins break even when the network is fine.
- Ping working doesn't mean the network works. My host firewall let ICMP through but dropped forwarded TCP and UDP.
- You can't link a GPO to the default `Users` or `Computers` folders. They're containers, not OUs.
- Computer policy follows where the computer is, and user policy follows where the user is. The domain password policy only works from the domain root.
- Service accounts with an SPN can be Kerberoasted. Any domain user can ask for their ticket, and it's encrypted with the account's password hash.
- Linux basics from TryHackMe and Bandit 0-5: hidden files, odd file names, quoting, wildcards and `find`.

## Commands or code worth remembering

```
# let VM traffic through ufw
sudo ufw route allow in on virbr10

# external snapshot of a UEFI VM (internal ones don't work)
virsh -c qemu:///system snapshot-create-as DC01 <name> --disk-only --atomic

# create the forest
Install-ADDSForest -DomainName purple.internal -DomainNetbiosName PURPLE -InstallDns

# join a client
Add-Computer -DomainName purple.internal -NewName WIN11 -Credential PURPLE\Administrator -Restart

# check the join
nltest /sc_verify:purple.internal

# check which GPOs applied
gpupdate /force
gpresult /r

# find Kerberoastable accounts
Get-ADUser -Filter "ServicePrincipalName -like '*'" -Properties ServicePrincipalName

# Bandit: files with odd names
cat ./-
cat "spaces in this filename"
find . -type f -size <N>c ! -executable
```

## What confused me

- Why `dcdiag` failed straight after promotion. Turns out those tests read the last 24 hours of logs, which were full of normal first-boot errors.
- Why `New-ADUser` said "already exists" after it had just failed. It makes the account before setting the password, so a bad password leaves a disabled account behind.
